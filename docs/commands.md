実行先は **PowerShell** です。コード枠内のコマンドだけをコピーしてください。以下のパスは現在のPC用であり、フォルダーやPythonの配置を変更した場合は読み替えます。

## 1. ローカルWebサーバーを起動する

ローカル表示先：<http://127.0.0.1:8000/>

自分のPCで編集結果を確認するための起動です。この操作だけで本番HPは更新されません。

### 最初に開発フォルダーへ移動

```powershell
cd "C:\Users\noriy\.codex\.chatgpt-projects\g-p-6ac32c1e2a108191911de2cc0943bee8\sites\mitamura-app"
```

### 通常の起動コマンド

```powershell
.\dev.ps1 serve
```

### スクリプト実行が禁止されている、というエラーが出る場合

Windowsの実行ポリシーでdev.ps1が止められる場合は、同じフォルダーで次を実行します。恒久的な実行ポリシー変更は不要です。

```powershell
& "..\..\.tools\php84\php.exe" artisan serve --host=127.0.0.1 --port=8000 --tries=1
```

`Server running on [http://127.0.0.1:8000]` が表示されたら、ブラウザでURLを開きます。このPowerShellは起動中のままにします。終了するときは `Ctrl+C` を押します。

ローカルDBにDockerを使用しているため、Docker Desktopと既存のDBコンテナも起動しておきます。DBが停止している場合だけ、別のPowerShellで同じ開発フォルダーに移動して次を実行します。

```powershell
docker compose up -d --wait
```

Dockerを起動するだけではLaravelのWebサーバーが起動するとは限りません。8000番ポートが使用中なら同じサーバーを二重起動せず、既存の起動ウィンドウを確認します。実行ポリシー以外のエラーは、この代替コマンドで必ず直るわけではありません。

## 2. コミット・プッシュした最新版を本番へ反映する

本番HP：<https://mitamurafarm.com/>

これは本番HPを実際に更新する操作です。ローカル表示用サーバーとは**別のPowerShell**を開いて実行してください。

### 事前準備

- ローカルで表示を確認し、自分の変更をコミットしてGitHub mainへプッシュします。
- コミット名の先頭は、Cursorの作業なら `[Cursor]`、ChatGPTの作業なら `[ChatGPT]` とします。
- 他方が作業中の未コミット変更を無断で巻き込みません。
- GitHubへのプッシュと本番反映は別の操作です。GitHubが最新版でも、それだけでHPが更新されるわけではありません。

### 実行フォルダーへ移動

```powershell
cd "C:\Users\noriy\.codex\.chatgpt-projects\g-p-6ac32c1e2a108191911de2cc0943bee8\sites\mitamura-app"
```

### 本番を変更せず確認だけしたい場合

```powershell
& "C:\Users\noriy\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" scripts/deploy-production.py --check
```

### 本番更新へ進むコマンド

```powershell
& "C:\Users\noriy\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" scripts/deploy-production.py --deploy
```

このコマンドは、コミット・プッシュ済みの最新版を、本番HPへ反映するためのプログラムを起動します。次の順番で進みます。

1. **ソースを確認**：未コミット変更がなく、手元とGitHub mainの最新版が一致しているか確認します。対応範囲外の変更があれば停止します。
2. **自動テストを実行**：問い合わせ処理などのPHPテスト、JavaScriptテスト、更新スクリプトのガードテストを実行します。問題があれば停止します。
3. **あなたが公開を確定**：表示された `publish コミット番号` を入力するまで、本番への反映は進みません。
4. **バックアップして反映**：既存の暗号化バックアップ処理を実行し、この回のGoogle Driveへの転送・照合が成功したことを確認してから、新しいコードへ切り替えます。
5. **公開後の確認**：公開ページと更新した静的ファイルを確認します。失敗した場合は、前の版への復帰を試みます。通信断・強制終了などでの自動復帰は保証しません。

注文データの削除・DB構造の変更・メール設定の変更は行いません。新たなテスト問い合わせやメールの送信も行いません。依存ライブラリ、DB構造、設定ファイル等を変更する作業は、この通常更新では停止して個別対応にします。

### publishの入力例（過去の成功時の例）

画面に `Type publish 79a4e282782c to update production:` と表示された際は、次を入力してEnterを押しました。

```text
publish 79a4e282782c
```

**これは固定の合言葉ではありません。毎回、実行画面に表示されたコミット番号を入力してください。** 上の番号は過去に公開した版の例です。PowerShellのプロンプトへ新しいコマンドとして入力するのではなく、更新プログラムの入力待ち欄へ入力します。

### 完了・エラーの見方

- `SUCCESS` と公開コミット番号が出たら、公開後の自動確認まで成功しています。本番HPを開いて `Ctrl+F5` で再読み込みし、変更箇所を確認します。
- `STOP` やエラーが出た場合は、繰り返し実行せず表示を確認します。`Local error log` が出たら、その場所に詳細ログがあります。秘密情報が含まれる可能性があるため、ログ全文をそのまま外部へ貼り付けません。
- `can't open file ... scripts/deploy-production.py` は、実行フォルダーが違う場合があります。まず上記の `cd` を実行します。
- 公開に成功した版・結果を[重要設定一覧](important-settings.md)と[作業記録](work-log.md)へ追記します。記録だけの変更に本番再デプロイは不要です。
