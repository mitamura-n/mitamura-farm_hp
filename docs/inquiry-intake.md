# 問い合わせ受付の実装と検証

更新：2026年10月19日。

## 実装済み

- 名前、返信先メール、複数の商品＋数量、分づき希望、都道府県、相談内容、個人情報利用の確認を入力。
- 内容確認画面→「この内容で受付する」→POST /inquiries→DB保存→農園通知・自動返信→受付番号を表示。
- 受付番号はMF-から始まるランダムなULID。注文確定とは区別する。
- 氏名・メール・商品明細・都道府県・本文はLaravelの暗号化キャストでDBへ保存。APP_KEYを失うと復号できないため、安全に保管し不用意に再生成しない。
- 商品・数量・精米の組み合わせ、必須項目、メール形式、都道府県、最大10商品をサーバーで検証。
- LaravelのCSRF保護、セッションにひもづいた送信キー、IP単位5回/分の受付制限、隠し入力欄による簡易対策。
- 同一送信キー・内容の再送は同じ受付番号を返し、DB保存・メール通知を重複しない。同じキーで内容を変えた場合は409。
- 保存が成功したあとに通知。メール失敗でも受付は残し、通知状態をfailedと記録する。通知の再送画面・自動リトライは未実装。
- 公開環境ではINQUIRIES_ENABLED=trueにするまで受付停止。開発localのみ既定で受付有効。
- メールのReply-Toは農園通知では相談者、自動返信では農園メール。送信元は別途SMTPに合わせて設定する。

## 現在のメール設定

MAIL_MAILER=logを確認済み。農園向け通知も自動返信もログへ記録し、Gmail等へ実送信しない。通知状態はloggedと保存する。開発ログには架空のテスト情報を含むメール本文があるため、Gitや公開領域に置かない。

## 検証

- 初期受付実装時の自動テスト全12件／56アサーション成功（現在の全体件数は検証結果の最新記録を参照）。複数明細の暗号化保存、通知先、重複防止、入力不備、同意なし、未知の商品・不適切な精米指定、別セッションのキー、通知失敗、10件超過、受付停止、連続送信、47都道府県の一意性を確認。
- scripts/smoke-inquiry.ps1でローカルの実HTTP受付を検証。CSRFなしは419、正しい送信は201、同一内容の再送は200・同じ番号。
- ローカルMariaDBに架空のテスト受付を1件保存済み。メール外部送信なし。
- 2026-10-19、Xserver上でブラウザーから入力→確認→受付完了を確認し、DB保存とメールlog状態を照合。最新の受付管理画面のスマホ表示は別途確認。

## 未完了・公開前の作業

管理者認証は実装済み。受付管理の進捗はroadmap.mdを参照。残作業は通知失敗の再送手順、配送先入力、金額案内・注文確定、正式な個人情報保護方針・保存期間・削除運用、外部SMTPと実メール到達確認、スパム対策の本番調整。

現在の個人情報説明は受付用途の簡易説明で、正式な公開用ポリシー全体ではない。取得は開発中テスト情報に限定する。

## SEOの公開準備

プレビューのnoindexを維持し、本番確認後に切り替える。公開時は商品別の説明、タイトル・description、画像の実物化・軽量化、canonical・sitemap・robots、旧URLからの移行、Search Console登録を整理する。検索順位改善や公開登録はまだ実施していない。
