# PHP本体の脆弱性への対応記録

対象：CVE-2026-109618 / CVE-2026-109619。確認日：2026-10-22（日本時間）。

## 本番・プレビューの確認状況

- PHP/Laravelを使用。公開入口farm-index.phpからLaravelへ渡し、ページ生成・受付のDB保存・メール通知・管理画面・旧HP保存版の閲覧を処理する。
- 公開中のcomposer.jsonはPHP ^8.4、Laravel ^13.0を要求。修正版であってもPHP 8.2/8.3へ下げない。
- XserverのSSHで /usr/bin/php8.4 がPHP 8.4.27であることを確認。リンク先は /opt/php-8.4.27/bin/php。
- /opt/php-8.4/bin/php-cgi と /opt/php-8.4/sbin/php-fpm もPHP 8.4.27。旧版の実行ファイルもサーバーには残っているため、設置済みであることと実際のWeb処理への適用完了は区別する。
- HTTP応答にはPHPバージョンが出ておらず、実際の本番・プレビューのWeb処理のバージョンと、既存ワーカーの再起動完了は未確認。
- Xserver公式サイトとログイン画面は調査時503で、予防的対策の停止案内と修正を順次適用する説明を表示。サーバーパネルの再開後、各ドメインのPHP設定と提供元の適用完了情報を確認する。
- 本調査でサーバーの設定・公開ファイル・current・DB・SMTPは変更していない。診断ページの設置、問い合わせ送信、攻撃の再現試験、脆弱性スキャンは実施していない。不正アクセスの有無は本確認では判定していない。

## ローカル開発環境

- 更新前：作業領域の .tools/php84/php.exe はPHP 8.4.26（Windows x64 NTS）。
- 公式のPHP 8.4.27 x64 NTSを取得し、既存php.iniを引き継いで別フォルダーで起動確認。
- 配布ファイルSHA256：93bd8a815a52156606fb906d0573437908c61f96e2cc52c03a51e36a41bf5236。公式掲載値と一致。
- DB・暗号化・メール等に必要な既存拡張のロードを確認。全56テスト385アサーション成功。初回実行と一部の切り分け実行は時間がかかったため停止したが、最終の全件実行は終了コード0で完了（テスト時間31.539秒）。

## 次に確認する内容

1. 本番とプレビューそれぞれのWeb用PHPに修正が適用されていることを確認する。コマンド用PHPの版だけで完了扱いにしない。
2. 未適用の場合はXserverの案内に沿って8.4系の修正版を使用する。8.5への変更やアプリ再デプロイを本件の必須作業とは扱わない。
3. 適用後は公開ページ・管理者ログイン・受付保存・二重送信防止・通知/受付メール・バックアップを確認する。実メール送信やバックアップの再実行は別途必要な範囲で行い、未実施と区別する。
4. 正常表示だけで脆弱性修正や過去の無被害を証明したとは扱わない。

## ローカル切替結果

- .tools/php84 をPHP 8.4.27へ切替済み。既存のPHP参照パスとphp.iniを維持し、OS全体のPATHは変更していない。
- 旧版は同じ作業領域内の .tools/php84-8.4.26-retired-20261022 に退避。「RETIRED-DO-NOT-USE.txt」を付け、通常利用・開発サーバーの起動に使わない。
- 切替前の修正版で全56テスト385アサーション成功。切替後の実行パスで8.4.27を再確認し、Composerのcheck-platform-reqs --no-devも成功。新規テストの追加やアプリコードの変更はしていない。
- 実SMTP送信、本番DBへの書き込み、バックアップの実行、本番デプロイは今回行っていない。
