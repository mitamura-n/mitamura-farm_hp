# 問い合わせの保管見直し手順

1. 管理画面の受付詳細で「注文の結果」を記録する。これは内部の分類で、注文の確定やメール送信は行わない。
2. 実際に対応が終わったときに対応状況を「対応完了」にする。終了日時は保存時に記録される。再開時は解除される。過去の終了日は推定して登録しない。
3. 一覧の「保管の見直し対象を見る」を開く。注文に至らず、対応完了から1年経過した記録のみ表示。未確認の注文結果・終了日未記録は抽出しないので別途点検する。
4. 継続対応・紛争・法令保存等の必要性を担当者が確認。対象表示だけで削除を決めない。
5. 不要と判断した情報はDB、Gmail、Xserverメールボックス、ログ、バックアップの保存先ごとに削除対象を整理。受付番号で照合し、他の記録や注文記録を巻き込まない。
6. バックアップの保管期限と復元時の再削除を運用に含める。削除履歴へ本文・氏名・メールを再保存しない。

現時点で実装済み：内部分類・終了日時・見直し時期表示・期限到来の一覧抽出。自動削除・削除ボタンはない。実データの削除は今回行わない。削除対象の確認・承認、各保存先の具体的削除とバックアップ世代管理は公開前に手順を完成させる。
