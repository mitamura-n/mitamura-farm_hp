## 1. このプロジェクトの目的と農園の方針

三田村農園は、福井県越前市中平吹町で、先祖代々の田んぼを受け継ぎ、農薬・化学肥料・有機肥料を使わない米づくりに取り組む農園です。コシヒカリの玄米・白米・分づき米と、そのお米を使った米粉・米ぬかを案内します。収穫後の乾燥・籾摺りを自家で行い、お米を低温保管し、白米は注文後に精米するという、確認済みの営みを伝えることを大切にしています。

HPでは、田んぼ・日野山・日野川・家族の物語を活かしながら、商品、価格、買い方が分かりやすく伝わることを目指します。「分かりやすく、見た目も美しく」が一貫した希望です。落ち着いた配色、読みやすい文字、余白、スマホでの操作性を重視し、説明の重複やシステム用語を減らします。

販売はネット通販・発送が中心です。親戚や知人への個別の手渡しはありますが、一般客向けの店頭販売・来店受付を行う方針ではありません。店舗の営業時間や来店案内を創作せず、Googleマップ・ビジネスプロフィールの店舗登録や地図の埋め込みも勝手に追加しません。

現在は、農園が在庫・精米・梱包・送料を確認してから金額を案内する、手動の見積もり方式で運用します。未確定な条件まで自動化せず、現場で無理なく回せる形を先に整えます。

## 3. 確定している販売・注文ルール

### 注文の成立まで

お客様はフォームから希望を送り、自動受付メールを受け取ります。農園が在庫・年産・精米・梱包・送料・手数料を確認し、メールで見積もりを案内します。お客様が金額と内容にご了承した後に注文を確定し、支払い・発送へ進みます。

フォーム送信や自動受付メールの時点では、注文・支払いは確定しません。見積もりと請求書を同じ意味で扱わず、未確定の段階で支払いを求めないでください。管理画面で対応状況を変えることも、顧客への連絡や注文確定を自動実行する操作ではありません。

フォームのご用件は「購入希望・お見積もり」「商品についてのご質問」「その他のお問い合わせ」の3種類です。購入希望を初期選択とし、必要な商品・数量・都道府県の入力条件を連動させています。

### 商品と数量

お米の通常選択は10kg単位で、フォームでは10～60kgを選べます。玄米は「10kg」、白米・分づき米は「玄米10kg分」のように表示し、「10kg×口数」をお客様に計算させません。米粉・米ぬかは袋数と規格に切り替えます。60kgを超える希望や袋分けは相談内容で受け付けます。

農園では5kg袋と10kg袋を使用していますが、5kg単位の通常販売を追加することはまだ決めていません。40kgなら10kg袋4袋を2箱に分ける例があります。すべての数量を30kg袋で届けるなどの仮定を置かないでください。

「白米・分づき米は精米後に約1割減る」という注記は、本人の希望で削除しています。重量基準の説明は保ちつつ、この注記を独断で復活させないでください。

確認時の参考価格は、お米が玄米重量10kg分10,000円、米粉1kg袋1,500円、米ぬか1kg袋1,000円で、いずれも税込です。価格・規格・受付可否は商品マスターが正であり、変更時は管理画面と実データを確認します。在庫や販売年産は返信で確認し、数量を推測して「在庫あり」と表示しません。

精米料は精米前の玄米重量で5kg100円、10kg200円、20kg300円、30kg400円（税込）の確認済み表があります。表にない重量は、未確認の比例計算や0円扱いをせず、個別案内にします。同じ商品・精米度合いの明細は、合計重量に応じて既存ロジックで計算しています。

### 送料・袋代・概算表示

送料表は農園が現在も有効と確認した料金を使用し、箱・梱包を含みます。表と概算は `config/shipping.php` を共通参照します。重量の判定には箱・梱包材も含めます。

送料込みの自動概算は「お米1種類を1つの明細で、10kgまたは20kg、通常配送」の場合に限って導入済みです。都道府県から地域別の100サイズ送料を加えます。米粉・米ぬか、混載、同一商品を複数欄に分けた場合、30kg以上、価格・数量未確定、離島・袋分けなどは個別見積もりとし、送料込み合計を推測しません。

表示は「小計（目安）」「送料（目安）」「送料込みの目安」とし、最終金額は農園からのメールで案内します。離島・袋分けなどのチェック内容は、確認画面と相談内容へ引き継ぎます。

通常のご注文では60kgでも袋代は受け取らない方針です。大口・特別な対応は人が判断します。通常注文に袋代を自動加算したり、すべてに別途袋代がかかるような説明へ戻したりしないでください。

### 支払い・発送・変更・返品

現在使える支払い方法は銀行振込・郵便振替・代金引換です。振込・払込・代引きの手数料はすべてお客様負担で確定しています。代引き手数料は税込330円です。以前の「銀行振込手数料は農園負担」は撤回されています。HP・メールひな形・受付メールで矛盾させないでください。

銀行振込・郵便振替は注文確定の案内から7日以内の支払い、入金確認後に通常2～3営業日以内に発送します。代引きは注文確定後に通常2～3営業日以内に発送し、受取時に支払います。営業日は土日・祝日を除き、遅れる場合はメールで案内します。

変更・キャンセルは早めのメール連絡をお願いし、精米・発送準備の状況に応じて判断します。食品のためお客様都合の返品・交換は未開封でも受け付けません。不良・破損・誤配送は到着7日以内を目安に連絡を受け、確認して農園負担で交換・返金に対応します。7日を過ぎた場合もまず連絡をお願いする案内です。返送前の連絡、可能なら写真、商品・梱包材の保管を案内しています。

## 4. 実装・整備済みの内容

アプリはLaravel 13 / PHP 8.4系、Bladeと通常のJavaScript/CSSで構成しています。本番DBはMariaDB、プレビューはSQLiteで、接続先は分けています。問い合わせの保存、暗号化、CSRF対策、入力検証、送信キーによる二重受付防止、管理者ログイン、商品管理、問い合わせ管理などを実装済みです。

フォームは確認画面を経て送信し、受付番号を表示します。農園向け通知とお客様向け受付メールの2通を送ります。送信済み内容を残したままロゴから戻って再送してしまう問題に対応し、完了表示と「新しいお問い合わせを入力する」導線を整えています。

送信元は `info@mitamurafarm.com`、対応窓口は `mitamura.farm@gmail.com` です。本番は一般のお客様への送信を許可し、プレビューの送信先は農園Gmailに制限しています。見積もり・注文案内等の文章は [order-mail-templates.md](order-mail-templates.md) にあります。これらをすべて自動送信する仕組みが完成したという意味ではなく、人が内容を確認して使う運用です。

トップには農園の物語・育て方・商品・お客様の声・注文の流れ・短いFAQ・問い合わせフォームを残しています。長い案内は `/tokushoho`（特商法）、`/privacy`（個人情報）、`/shipping`（送料・発送・返品）へ独立させ、トップには要約とリンクを置いています。従来の `#delivery` 等のアンカーも要約の目印として残しています。URLの「#」部分はサーバーへ送られないため、サーバーの301だけで任意の旧アンカーを振り分けられると考えないでください。

レビューはトップの商品案内の後に3件掲載済みです。見出しは「お客様の声」。旧HPの実際の文章から味・食感の感想を抜粋し、本人希望により「旧HPに寄せられた」等の説明・年月・地域・氏名は出していません。感想や評価点を創作せず、病気・健康効果の体験談を転載しない方針です。

旧HP全体は一般公開せず、管理者だけがブラウザで参照できる保存版として残しています。旧URLは新HPの対応箇所へ転送し、旧CGIは終了案内にしています。新HPから一般客向けに旧HP全体を再公開する方針ではありません。

## 8. Cursor AIとChatGPTの作業ルール

「どう思う？」「～の方がよくない？」という相談は、変更指示ではありません。現状・候補・理由を説明しておすすめを示し、「それでいこう」「修正して」等の採用・実行意思を確認してから変更します。反対のための反対や根拠のない賛同は不要です。

利用量の上限が厳しいため、本人ができる写真選び・スマホ確認・メール/審査確認は本人にお願いし、AI側は素材・指摘をまとめて受けて一括修正する進め方を重視します。大量のブラウザ操作、同じ画面の再確認、不要な全件テストを繰り返さないでください。通常の小さな実装判断は採用済み方針に沿って進め、結果をまとめて報告します。

作業前に `AGENTS.md`、Gitの状態、最新の重要設定を確認し、既存の未コミット変更を上書き・巻き込みコミットしないでください。この文書の作成開始時にも `resources/views/farm.blade.php` に未コミット変更がありました。変更者や内容の採用を推測せず、必要な範囲で確認します。共有フォルダーなら同じファイルの同時編集を避け、別クローンならcommit/push/pullで同期します。

2026年10月22日の本人指定により、今後のコミットメッセージの先頭には、作業を担当したAIに応じて `[Cursor]` または `[ChatGPT]` を必ず付けます。自分の変更だけをステージし、双方の変更は原則として別コミットにします。識別子は運用上の記録であり、作業者の技術的な証明ではありません。このルールのために過去の履歴を書き換えることはしません。

変更に応じた検証を行い、ソースと関連記録をコミット・プッシュします。ただし、コミット、プレビュー反映、本番反映、実環境での確認は別の完了条件です。引き継ぎ文書を作る依頼だけを根拠に、本番配置や設定変更まで実行してはいけません。既存のデプロイ手順には公開前用の制約が残っている場合があるため、稼働中の本番へそのまま適用しないでください。

メール・DB・認証・決済・公開・バックアップ・解析の重要変更は、[important-settings.md](important-settings.md) と [work-log.md](work-log.md) を更新します。成功・未確認・未実施を分け、秘密情報を記録しません。APP_KEYの不用意な再生成、DBの初期化、秘密鍵の再作成、公開ディレクトリへの環境設定のコピー等を行わないでください。

リポジトリのPHP要件は8.4系です。ChatGPT側の確認済みローカル実行パスは `../../.tools/php84/php.exe`（リポジトリ基準、8.4.27）。Cursorが別クローンなら、その環境のPHP実行パスを確認してください。通常の `php` が古いXAMPPのPHPを指す場合があるため、版を確認します。PHPUnitと `node --test tests/*.test.cjs` 等を変更箇所に応じて実行し、実SMTP送信や本番DB書き込みを通常のテスト実行に混ぜないでください。

最後に、実装・文言・運用を変える前には「今の公開サイトで何が動いていて、何がまだ未確定か」を確認してください。この文書は引き継ぎ時点の整理であり、記載された候補をすべて即実装する一括指示ではありません。

## Cursorへ最初に渡す依頼文

> `AGENTS.md` と `docs/cursor-handoff.md`、`docs/important-settings.md` を読み、現在の公開状態・採用済みの運用方針・未確定事項を把握してください。最初はGitの既存変更と現在地を確認し、勝手に変更・本番反映せず、今回お願いする作業の範囲に沿って進めてください。過去の未定記述より最新の確定事項を優先し、秘密情報を出力・コミットしないでください。
